# 原生悬浮速记窗 + 任务/阅读小部件 需求规格

> 复刻 QuickDaily（/tmp/opencode/QuickDaily）的原生小窗口体系，解决「点小部件/磁贴会打开整个 App」的问题。

## 背景

当前桌面小部件 `QuickNoteWidgetProvider` 与磁贴 `QuickNoteTileService` 点击后都拉起 `MainActivity`（Flutter 主界面），用户需要"速记就速记，别把整个软件打开"。QuickDaily 用**纯原生悬浮窗**（`TYPE_APPLICATION_OVERLAY` 的 `FloatingNoteService`）和**透明悬浮形态 Activity**（`NoteEditActivity`）绕开主界面。

本规格采用**纯原生悬浮窗（Java）**路线：原生侧直接读写 md 文件，Flutter 侧启动时扫描导入草稿箱。

## 用户需求

### 需求 1：速记悬浮窗（核心）

- R1.1 点击桌面小部件 / 通知栏磁贴 /（可选）桌面图标，**只弹出速记悬浮窗，不启动 MainActivity**。
- R1.2 悬浮窗形态：宽约 88% 屏宽、高约 35% 屏高，局中偏上，可拖拽，位置记忆。
- R1.3 悬浮窗内容：标题栏（关闭 + 标题 + 保存）+ 多行输入框 + 底部工具栏（时间戳 / 加粗 / 列表 / 保存）。
- R1.4 打开时自动聚焦输入框并弹出键盘。
- R1.5 输入自动草稿保存（进程被杀 / 关闭后重开恢复草稿）。
- R1.6 保存逻辑：构造 md 文本（含锚点、时间戳、用户内容），写入应用私有目录 `MD文章/` 下的 md 文件。
- R1.7 点击外部 / 返回键关闭；关闭时按 `save_on_close` 决定保存还是留草稿。
- R1.8 保存成功后关闭悬浮窗，显示 toast「已保存」。

### 需求 2：草稿同步（原生 md → Flutter 草稿箱）

- R2.1 原生速记产生的 md 文件落盘在 `<filesDir>/MD文章/` 目录，文件名带时间戳唯一标识。
- R2.2 Flutter 启动 / 进入草稿箱时**扫描该目录**，将新增 md 文件导入为草稿 `Article`，导入后标记已处理（避免重复导入）。
- R2.3 导入的草稿可在 App 草稿箱中正常打开、编辑、发布。

### 需求 3：任务小部件

- R3.1 桌面小部件展示草稿内容中 `- [ ]` / `- [x]` 任务行列表。
- R3.2 支持点击切换任务勾选状态，状态写回对应 md 文件。
- R3.3 支持刷新按钮与空态文案。

### 需求 4：阅读小部件

- R4.1 桌面小部件展示指定草稿 / 文章的 md 内容预览。
- R4.2 支持 markdown 渲染开关、任务行勾选。
- R4.3 提供「打开编辑页」「加号速记」入口。

## 非目标

- 不实现跨应用悬浮（悬浮窗仅在本 App 内为透明悬浮形态 Activity，服务用 TYPE_APPLICATION_OVERLAY 实现系统级悬浮 —— 按实现方案决定）。
- 不实现录音、拍照、附件（后续迭代）。
- 不改造 Flutter 现有速记浮层 `QuickNoteFloater`（保留，作为 App 内入口）。

## 成功标准

- 点小部件/磁贴：只出现悬浮速记窗，不出现 Flutter 主界面。
- 悬浮窗输入 → 保存 → 关闭 → 打开 App → 草稿箱出现该速记。
- 任务小部件能列出并勾选任务；阅读小部件能预览内容。
